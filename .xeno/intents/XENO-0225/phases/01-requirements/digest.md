A link naming a document that is not in the tree is a G-Schema finding naming the component, the path
and that the file is not there, with the profile as the file it names, because the profile is what is
wrong. A link whose document exists is unchanged: it joins the base with its hash, last, as #171
settled. The check reads the profile from P0 whatever phase is judged, which is what the budget check
established — a profile mistake is the intent's and not one phase's — and it does not block. A profile
with no links and a repository with no profile both produce nothing. Non-goals, and they are where the
argument lives: no field in the lock, because recording the byte count changes section 5's enumeration
and is a person's commit; no refusal at `phase start`, because a second mechanism for one error makes
the cheap check the loud one; no validation of `include` or `exclude`, because a pattern matching
nothing is legitimate — the files may not be written yet; and no check that a link's component exists,
because a component is a path prefix in the project's own vocabulary and may not be a directory at all.
The document is the part that is unambiguously a file, which is why it is the profile's only
unambiguous error.
