The paragraph is replaced rather than annotated, because a removal annotated in place reads as a
mechanism with a caveat, and it carries both measurements rather than the conclusion — a removal
somebody can reinstate by disagreeing with an absence will be reinstated, where one they must
disagree with evidence to reinstate is a decision. `XENO_PLUGIN_ROOT` leaves the list and three
remain, because leaving it listed while the paragraph below said there was no order would be the
half-agreeing document this change exists to avoid. One sentence is kept about the condition any
override would have to meet, discovered by measurement and worth more written down than
rediscovered; and the client fallback's unreachability is kept too, because it looks useful and
cannot work, which is worth a reader's time where silence would invite its reinstatement. Six
alternatives refused, including one of my own recommendations made twice and retracted here: the
split by purpose breaks the case the fallback existed for, since a project relying on a client's
plugin could not resolve templates — visible only once somebody ran an un-vendored project. Also
refused: the order under a condition, declined for the mechanism it would leave to maintain; the
order as written with A42 amended, declined for what weakening A42 costs; and marking the clause
unimplemented, which is a state a gate can report and a resolution order cannot. Nothing in the code
changes, which is the point — the code was already what the document now says.
