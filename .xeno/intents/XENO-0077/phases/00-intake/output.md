# Intake

<!-- xeno:section:problem -->
## Problem

Section 10 fixed a learning's `target` as a path under
`.xeno/config/rules/learned/project/` and said that a learning produces a merge request
against the rule set. The repository has no rules tree: the engine is WP4. So a target
in that form named a file nothing reads, six records did exactly that, and seventeen
named `CLAUDE.md` instead, where several of those rules are today. The census is on #64,
found while the same shape of problem was being fixed on the hash fields.

<!-- xeno:section:scope -->
## Scope

What `target` means, in section 10, and the interim case it admits: a rule the engine
applies keeps the rules path, and a project convention may name the file a project reads
before it acts. The length of that file is the test for whether a convention earns a
line in it.

D-4 records the revision, because the row said "never into `CLAUDE.md`" and would
otherwise contradict the section.

Nothing in the trail is re-sealed and no gate changes here. What #64's gate should
enforce is now decided rather than open.

<!-- xeno:section:context-rationale -->
## Why this context

**One of D-4's two reasons failed and the other did not.** The decision gave two: a line
in that file is a standing cost on every request of every session, and a rule written
there would take effect unreviewed. The second did not materialise, because every such
rule arrived through a pull request; what nobody did was edit the file where the
learning was noticed, which is the act the route exists to prevent. The first is
unaffected by any of this and is the test the section now states.

**The practice was not sloppiness, it was a missing alternative.** Before WP4 a learned
rule has no engine, so a convention naming the rules path would take effect never and
one naming the file that is read takes effect at the next session. Seventeen records
chose the second. A section that admits it says what the project does; one that forbids
it would be a rule kept by nobody, and a gate written from it would red seventeen sealed
records over a route that does not exist.

**What stays strict.** The route is unchanged, a record in a phase and a reviewed merge
request. The interim target is allowed for `project-convention` only, so a template or a
prompt change cannot use it, and it disappears by itself once the engine exists, since a
rule the engine applies has a path of its own.
